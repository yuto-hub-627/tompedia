# とんペディア スライド作成スキル（Canva）

とんペディアで使うスライドを、Canvaのブランドテンプレート `EAG_b_rCz2M` から作る。
ゼロから新規デザインを生成しない。フォントはCanva MCPから指定できないので、**型ページの既存テキストを `replace_text` で差し替えて作る**。

参照ファイル（作業前に必ず読む）:
- `references/design-spec.md` … 色・フォント・フレーム4種・座標・文字数の上限
- `references/layout-catalog.md` … 22ページの型、差し替える要素、内容から型を選ぶ判断表
- `references/extra-layouts.md` … テンプレートにない型（実例の資料から持ってくる18種）と、見つからなかった型
- `references/question-template.md` … 資料ごとの質問mdのひな形

PowerPoint版の `tonpedia-slides`（アカウントのスキル）は使わない。.pptxが必要なときは、このスキルでCanvaに作ってから `export-design` で書き出す。

## 全体の流れ

```
依頼 → [1] 質問mdを書く → ユーザーが回答 → （必要なら2往復目）
     → [2] 構成を決めて記録 → [3] Canvaで作る → [4] プレビュー・OKで保存
     → [5] 修正の往復（mdかチャット）
```

ユーザーとのやりとりは **mdファイルで質問 → ユーザーが `[Answer]:` に回答** が基本（ユーザーの方針）。チャットで答えが返ってきた場合はそれも使う。

## Step 1：質問mdを書く（Inception）

1. 依頼から資料名を決め、フォルダ `aidlc-docs/slides-YYYYMMDD-<英数字の短い名前>/` を作る（例：`slides-20261020-zentaikai`）。
2. `references/question-template.md` をもとに `01-questions.md` を書く。
   - 依頼文・渡された資料（チャットのメモ、Googleドキュメント／スライド、Markdown）からわかることは**先に埋めて「この理解で合っていますか」と聞く**。わからないことだけを質問にする。
   - 選択式（A/B/C、X＝その他）を基本にし、1回の質問は10問前後まで。
   - 文章をそのまま使うか、Claudeが書くかは**ページ（章）ごとに**選んでもらう。
3. コミットしてpushし、ユーザーに次を伝える：
   - 編集リンク：`https://vscode.dev/github/yuto-hub-627/tompedia/blob/<ブランチ>/<mdのパス>`
   - 書き終わったら、左のソース管理アイコン → メッセージを入れて「コミットしてプッシュ」→ チャットで知らせてもらう
4. 回答をpullして読む。足りない・矛盾がある場合だけ `02-questions.md` で2往復目をする。推測で埋められる細かい点は質問せず、Step 2の記録に「仮定」として書く。

元ネタがGoogleドキュメント／スライドなら Google Drive・Docs・Slides のコネクタで読む。

## Step 2：構成を決めて記録する

`layout-catalog.md` の「内容 → 型の対応」で、ページごとに型を決め、`outline.md` に書いてコミットする。**ユーザーの確認は待たずに Step 3 へ進む**（ユーザーの方針：Canvaで見て直す）。

```
| P | 型（テンプレのページ番号） | ページタイトル | 大見出し／メッセージ | 本文・箇条書き | 写真 | ノート |
```

決め方のルール：
- 表紙：外部向け＝P1、ラボ内部・MTG・勉強会＝P2、営業部＝P3。
- 章が3つ以上 → P4 目次＋章ごとに P5（1行タイトル）／P10（2行タイトル）。
- 本文は基本 P6（見出し＋本文）。テンプレートにない形（理想／現状、2カラム、3ステップなど）は `extra-layouts.md` の型を使う。
- **`layout-catalog.md` にも `extra-layouts.md` にもない型が必要なら、作る前にユーザーに相談する**（質問mdに書く）。表・タイムテーブルは公式フレームの実例がないので必ず相談。
- 最後のCHECK!（P22）は**指示があったときだけ**入れる。
- 紹介資料の実例ページ（P12〜P21）の数字は最新なので、団体・アプリ紹介ではそのまま使ってよい。
- 1スライド1メッセージ。箇条書きは3〜5項目、2段まで。文字数の上限（`design-spec.md`）を超えるなら2枚に分ける。

## Step 3：Canvaで作る（Construction）

### 3-1. ページをそろえる（2026-10-20 の試作で確認した手順）
1. `create-design-from-brand-template`（`brand_template_id: EAG_b_rCz2M`）を **`page_numbers` なしで** 呼ぶ。22ページのデザインが新しくできる（＝作業用の元。以下「元デザイン」）。
   - `page_numbers` を付けると「not found」エラーになる。
2. `merge-designs`（`type: create_new_design`、`title: YYYY-MM-DD_資料名`）で、元デザインから使う型を**並べたい順に**1回で入れる。
   - `operations` は **1つだけ**（`insert_pages` 1回）。複数の操作を送るとエラーになる。
   - `page_numbers` は**繰り返してよい**（例：`[2, 6, 21, 6, 6, 7]`）。
   - `copy-design` は同じページ番号を繰り返すと「not found」エラーになるので使わない。
3. テンプレート外の型は、できたデザインに `merge-designs`（`modify_existing_design`、`insert_pages`）で `extra-layouts.md` の元デザインから足す。
4. 元デザイン（22ページ）は使い終わったら不要。MCPからは削除できないので、最後にユーザーに「ゴミ箱に入れてよい」と伝える。

### 3-2. 文章を差し替える
1. `read-design` に `open_transaction: true` を付けて要素一覧（locator_id）を取る。出力が大きいので、ページを数枚ずつ（`page_indices`）読む。
2. `edit-design`（`finalize: "keep_open"`）で、ページごとに `replace_text`。
   - 本文・見出しは `add_text` で作らない。`add_text` の文字は別の書体（`YACgEZ1cb1Q`、16px・黒）になる。文字の枠が足りなければ、同じ型のページを増やすか、同じページの既存テキストを流用する。
   - **表だけは例外**：P7（空の本文カード）に `insert_shape` で見出し帯（`#825dab`、角丸12、高さ80）としま模様の行（`#f6efff`、高さ80、1行おき）を置き、列ごとに `add_text` を1つ置いて `format_text`（34px・bold・行間2.35＝1行80px）で行にそろえる。見出しの文字は白、日付など1列目は紫、本文は `#242323`。書体の違いは小さく、表としては問題なく見える（試作で確認）。
   - 使わないテキスト要素（目次の04・05など）は `delete_element`。
   - 図解が必要なら、ボックス・矢印は `insert_shape` で足してよい（色は `design-spec.md` のパレットだけ）。文字はボックスの中ではなく、既存テキストを `position_element` で重ねる。
   - 長い文章は枠の幅に合わせて `\n` で改行を入れる（1行の文字数は `design-spec.md`）。
3. スピーカーノートを全ページに入れる（`replace_speaker_notes`）。話し言葉で、1ページ150〜300文字。スライドに書ききれなかった補足・数字の出典もここに書く。
4. テンプレートの元の文言（「スライドタイトル」「テキスト」「サンプル」「背景：とんペディア」など）が残っていないか、`read-design` の全文で確認する。

### 3-3. 写真
- ユーザーが渡した写真だけを使う。Drive → `upload-asset-from-url` かダウンロードして `create-upload-url`、Canvaにある写真 → `get-assets`。
- `update_fill` で差し替える（`alt_text` に何の写真か）。
- 写真がない写真枠は、型の写真のまま残し、最後に「差し替えが必要な写真枠：P5の背景…」とリストで伝える。

## Step 4：プレビューして保存する

1. `read-design` で全ページのサムネイルを取り、確認する：文字のはみ出し・重なり、元の文言の残り、ロゴ・装飾が動いていないか。
2. 直せるものは直す（文章を短くする → それでもだめなら `resize_element`。フォントサイズは最後の手段）。
3. サムネイルを見せて「この内容で保存してよいですか？」と1回だけ聞く。**OKが出るまで `commit` しない**（Canvaの仕様。ユーザーの方針は「構成の確認は不要」なので、ここ以外では確認を挟まない）。
4. 保存したら `move-item-to-folder` で保存先フォルダ「中西悠仁」（`FAHYd2F4Mo0`、プロジェクトの個人フォルダ内）に移す。
5. 編集URL、残っている作業（写真・要確認）を伝え、`outline.md` にデザインIDとURLを追記してコミットする。

## Step 5：修正

- 「P3の文章を短く」など小さい修正はチャットで受けてそのまま直す。
- 構成を変えるような大きい修正は `0N-feedback.md` に質問として書き、回答をもらってから直す。
- 直したら同じく Step 4 の確認をする。

## やってはいけないこと
- `generate-design` などでゼロから作る（型の見た目が再現できない）。
- ブランドテンプレートや既存の資料（`DAHQTwPXwu4`、`DAHXIFJiZ5I` など）を直接編集する。
- `add_text` で本文を作る。
- ユーザーの承認なしに `commit` する。
- 数字・実績・参加者の声・人名を**捏造する**。不明な点は `【要確認：〇〇】` と書いて残す。
- ロゴ・ブロブ・背景の円・カード・マスコットを動かす・色を変える。
