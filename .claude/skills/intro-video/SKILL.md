# 動画作成スキル（とんペディア）

これまでに作った2本で固まった流れ。新しい動画もこの流れと仕組みで作る。

| 例 | 型 | 場所 |
|---|---|---|
| アプリ「とんペディア」紹介動画 | **アプリ画面型**：アプリの操作動画をスマホ枠で見せる。ナレーションなし、文字と効果音だけ | `video/app-intro/`、`aidlc-docs/intro-video/` |
| 団体「とんペディア_ラボ」紹介動画 | **写真＋ナレーション型**：メンバーの写真・動画を大きく見せ、ナレーションで語る。アプリ画面は1場面だけ | `video/labo-intro/`、`aidlc-docs/labo-intro/` |

新しい動画は `video/<動画名>/` と `aidlc-docs/<動画名>/` を作り、近いほうの例の `overlay.html`・`build.sh` をコピーして直す。`render-overlay.mjs`・`sfx.py`・`add-bgm.sh`・`build-gc.sh`・`gc-card.html` は `video/app-intro/` のものをそのまま共有して使う（例のフォルダ自体は壊さない）。

## 1. 進め方（AIDLC）

各段階のドキュメントをリポジトリに置き、コミット・プッシュしてから次へ進む。

1. **素材の棚卸し** `00-material-inventory.md`：Drive の `tompedia` フォルダ（特に `とんペディア紹介動画`、`Figma用`）と https://slide.tompedia.jp/ から、使える動画・画像・音声・数字を一覧にする（前の動画の棚卸しで足りれば省略してよい）。
2. **記入シート** `01-requirement-questions.md`：`templates/requirement-questions.md` をコピーして作る。**決まっていることは先に書き込み**、ユーザーには直すところと台本だけ書いてもらう。選択肢には「前の動画と同じ」を入れる。vscode.dev のリンク（`https://vscode.dev/github/yuto-hub-627/tompedia/blob/<ブランチ>/<パス>`）を渡す。回答は `git fetch` して読む。
3. **要件** `02-requirements.md`：回答を表にまとめる。主役（何をいちばん伝えたいか）を必ず1行で書く。
4. **絵コンテ** `03-storyboard.md`：秒ごとの場面表、ナレーション、**お願いしたい素材（写真・録音）の一覧と枚数**、BGM候補。修正のたびに版（v番号）を上げる。
5. **素材のお願いと BGM 選び**：写真・録音の一覧と BGM 候補3つをチャットで伝える。締め切りが近いときは、これを最優先で返す。
6. **仮版**：素材を待たずに、写真は「仮：〇〇」と書いた紫の板、録音は無音のまま動画を作って送る。流れ・文字・動き・BGMの入りを先に見てもらう。
7. **素材の差し替え → 修正**：届いた写真・録音を入れて作り直す。指摘を1つずつ反映し、版を上げてコミット・プッシュ。
8. **仕上げ**：GC版・BGM入りを作り、Instagram 投稿文 `04-instagram-caption.md` を書いて Drive にも保存する。

毎回、動画を作ったら主な場面を静止画にして並べた一覧（ffmpeg の `tile`／`hstack`）で目で確認し、音は音量の数値（`volumedetect`、`ebur128`）で確認する。**音は聞けないので、数値だけで確かめたと伝える。**

## 2. このユーザーの好み（これまでの指摘から）

全体
- 縦 1080×1920、30fps、30秒前後、ポップ。色は紫 #825dab ×白、強調に黄色。文字は M PLUS Rounded 1c。
- **最初のロゴ画面は1.8秒**。とん平（豚のキャラクター）は各場面に小さく出す。
- **ぶつっと切れる切り替えは嫌**：場面はクロスフェード。続きものの区切り（機能1→2→3、開発→営業→広報）は左へのスワイプではっきり分ける。
- 効果音は**少なめ・シンプル**。AIっぽい電子音は避け、実録音系（Kenney の CC0 素材）を使う。とん平が出るときの音・ロゴのポン・最後のポン・連続するピコピコは入れない。
- **BGM はロゴ画面（または冒頭の黒画面）から明るい場面に切り替わる瞬間に始める**（`add-bgm.sh` の6番目の引数）。全体は -16 LUFS 前後。
- 最後は「くわしくはホームページへ」だけ（URLは画面に出さない）。
- 動画ごとに**主役をはっきりさせる**。ラボの動画では「アプリより団体を伝えるのがメイン」と言われた。脇役（アプリ・イベント）は「実績」として短めにする。
- 強調したい語以外の文字は小さく。1行に収まらない文字は、折り返さずに文字を小さくする。

アプリ画面型
- アプリの画面は**スマホの枠に入れて**見せる。上の時計・電池は切り落とす。下のナビバーは最新版（全部アイコンが埋まったもの）にそろえる。説明カードはスマホに重ねず下に置く。
- 操作動画は速すぎないように（0.85〜1倍）。途中から始まったように見せない（立ち上げた画面・止まった画面から始める）。

写真＋ナレーション型
- 台本どおりに読むと長すぎることが多い。**日本語のナレーションは1秒に7〜8文字**で計算し、30秒なら全部で200文字ぐらいまでに短くする。短くした版を文ごと（N1, N2, …）の表にして、文字数と秒数の目安を添える。数字は読み方も書く（例：「ろくせんななひゃくにじゅうにん」）。
- 録音はメンバーにお願いする：スマホのボイスメモで、静かな部屋、1文ずつ別ファイル（`n1`〜）、前後に1秒の無音、同じ人が同じテンションで。
- 写真は場面ごとに「何が写っている写真を何枚」と具体的に頼む（縦向きが理想、横でも真ん中を切り抜く、動画3秒以上でも可）。
- 引き締めたい一言（スローガンなど）は黒背景・白文字・「ドーン」で出す。この場面はBGMなし。

## 3. 仕組み

| ファイル | 役割 |
|---|---|
| `overlay.html` | 映像の上に乗るもの（テロップ・とん平・スマホ枠・写真）を全部HTML/CSSで作る。`setTime(t)` で時刻 t の見た目になる。場面表 `S` はロゴ画面の長さ `OPEN`（`?open=` で渡す）からの相対時刻。音のタイミングも `window.SFX_CUES` に書く（効果音もナレーション `n1`〜も同じ仕組み） |
| `app-intro/render-overlay.mjs` | Playwright で HTML を1コマずつ透明PNGに書き出し、`sfx_cues.json` も出す。別フォルダのページは `--page ../<動画名>/overlay.html` |
| `build.sh` | 映像・テロップ・音を ffmpeg で合成。`OPEN=1.8 ./build.sh <assets> <footage> <work> <out.mp4>` |
| `app-intro/sfx.py` | 効果音とナレーションを、音量をそろえてタイミングどおりに並べる |
| `app-intro/gc-card.html`・`build-gc.sh` | GC版：最後に白いカード（ラボのロゴ＋「は」／Giving Campaign 2026 に参加中（青 #1e2b99）／Canva の GC 投稿画像／「投票お願いします！」）をクロスフェードでつなぐ。`build-gc.sh <assets> <普通版.mp4> <work> <out.mp4>` |
| `app-intro/add-bgm.sh` | BGM を重ねる（冒頭の声の間は下げる、最後1.5秒でフェードアウト、-16 LUFS）。`add-bgm.sh <動画> <BGM> <out> 0 <BGMの音量 -24> <音楽を始める秒>` |
| `*/sfx/` | Kenney の CC0 効果音とライセンス（`labo-intro/sfx` に「ドーン」用のパンチ音） |

写真＋ナレーション型（`labo-intro`）の作り
- 写真は `assets/photos/<名前>.jpg`。**ファイルがなければ「仮：〇〇」の紫の板**になるので、素材がそろう前でも作れる。届いたら名前を合わせて置いて作り直すだけ。
- 録音は `assets/narr/n1.*`〜（形式は何でもよい）。前後の無音を切り、低音・ノイズを削ってコンプで整える。なければ無音。
- 写真が全面に出る場面どうしは、「次の場面が上からフェードインし、前の場面は覆われるまで出したまま」にする（両方を半透明にすると真ん中で暗くなる）。
- アプリ画面を出す場面は、その場面の背景に穴をあけ、下に ffmpeg でアプリの録画を置く（`#sc-app.hole`）。
- 「ドーン」は build.sh の中で作る（下がっていく低音のサイン波＋Kenney のパンチ音＋短い残響）。

素材の取り方
- **イベントの実績**：イベントレポートの表紙を Canva の `export-design`（png、1ページ目、幅540）で書き出して並べる。デザインIDは `.claude/skills/event-report/references/catalog.md`。
- **BGM**：OpenTracks（旧DOVA-SYNDROME。商用OK・クレジット不要）から歌なしの明るい曲を3つ選んで出す。カテゴリーは `https://opentracks.com/bgm/category/<hope|refreshing|rock|pop|passion>/`。**ストリーミング配信している・配信向けに調整したと書かれた曲は外す**（SNSの著作権自動検出に引っかかるおそれ）。ダウンロードは、`/bgm/detail/<id>/download` のページの `csrfmiddlewaretoken` を付けて同じURLに `track=1` を POST し、返ってくる302の `location` から mp3 を取る（クッキーを保持する）。
- **Drive の大きい動画**：ユーザーに「リンクを知っている全員」に共有してもらい、`drive.usercontent.google.com` から curl で落とす。
- 作業用の素材と途中ファイルはスクラッチパッドに置き、リポジトリには入れない。完成品だけ `output/` に置く。
- コマ書き出しは時間がかかる（1本数分〜10分）。`run_in_background` で回し、タイムアウトは長め（30分以上）にする。

## 4. 出力と納品

- 出力は普通版／GC版 × BGMなし／BGM入り。普通版とGC版は**別ファイル**にする。仮版はスクラッチパッドから送り、リポジトリには入れない。
- ファイル名：`tompedia_<動画名>_v<版>[_gc][_bgm].mp4`（比較用に作るものは `_open18` のように違いを名前に入れる）。比較用は採用が決まったら消す。
- **Drive への動画のアップロードはできない**（Drive MCP は中身をbase64でツールに渡す方式で、数MBの動画は送れない）。動画はチャットで送り、Drive の `とんペディア紹介動画` フォルダ（ID `1aBIyxdPBBv7bL56dQQCbvkAq1iIfYfI2`）へはユーザーに置いてもらう。テキスト（投稿文など）は Drive に保存できる。
- Drive に文章を保存するときは `create_file` の `textContent`／`base64Content` どちらでも絵文字が文字化けする。保存後に Google Docs の `replaceAllText` で直し（文字化けした文字列は絵文字のUTF-8をLatin-1として読んだもの）、読み返して確認する。
- 既定のブランチは `claude/sweet-rubin-gdehsz`（`main` はない）。まとまったらPRを作り、ユーザーの指示でマージする（Squash and merge にすると、途中で消した動画が履歴に残らない）。

## 5. Instagram 投稿文

`aidlc-docs/<動画名>/04-instagram-caption.md` に普通版・GC版の2つを書き、同じものを Drive の `とんペディア紹介動画` フォルダに Google ドキュメントで保存する。

- 1行目は動画の冒頭と同じ言葉（問いかけ・スローガン）にする（最初の2行しか見えないため）。GC版は先頭に GC 参加と投票期間。
- 文言・数字は動画のテロップ・ナレーションとそろえる。主役が団体なら、アプリは実績として書く。URLは「プロフィールのリンクから」。
- わからない情報（投票ページのURLなど）は作らず `【要確認：〇〇】` にする。
- ハッシュタグは10個前後（#とんペディア #東北大学 #東北大 #東北大生 #仙台 #大学生 など。ラボなら #とんペディアラボ #学生団体、GC版は #GivingCampaign #GivingCampaign2026 も）。
