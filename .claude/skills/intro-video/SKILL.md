# 動画作成スキル（とんペディア）

アプリ「とんペディア」紹介動画（`video/app-intro/`、`aidlc-docs/intro-video/`）で固まった流れ。新しい動画もこの流れと仕組みで作る。
新しい動画は `video/<動画名>/` と `aidlc-docs/<動画名>/` を作り、`video/app-intro/` のスクリプトをコピーして直す（app-intro 自体は壊さない）。

## 1. 進め方（AIDLC）

各段階のドキュメントをリポジトリに置き、コミット・プッシュしてから次へ進む。

1. **素材の棚卸し** `00-material-inventory.md`：Drive の `tompedia` フォルダ（特に `とんペディア紹介動画`、`Figma用`）を探し、使える動画・画像・音声を一覧にする。参考に https://slide.tompedia.jp/ も見る。
2. **質問** `01-requirement-questions.md`：選択肢つきの質問ファイルを作り、ユーザーが vscode.dev 上で答えられるリンク（`https://vscode.dev/github/yuto-hub-627/tompedia/blob/<ブランチ>/<パス>`）を渡す。聞くこと：縦横・長さ・トーン・ナレーションの有無・見せたい機能と順番・入れる数字・最後の誘導先・納品形式。
3. **要件** `02-requirements.md`：回答をまとめる。
4. **絵コンテ** `03-storyboard-*.md`：秒ごとの場面表、使う映像の区間表、効果音・声・BGM。修正のたびに版（v番号）を上げて更新する。
5. **制作 → 確認 → 送る**：動画を作ったら、主な場面を静止画にして並べた一覧（ffmpeg の `tile`）で目で確認し、音は音量の数値（`volumedetect`、`ebur128`）で確認する。音は聞けないので、そう伝える。`SendUserFile` で動画を送る。
6. **修正**：ユーザーの指摘を1つずつ反映し、版を上げてコミット・プッシュ。古い版の出力は `output/` から消す。
7. **仕上げ**：GC版・BGM入りを作り、Instagram 投稿文 `04-instagram-caption.md` を書いて Drive にも保存する（下記）。

## 2. このユーザーの好み（これまでの指摘から）

- 縦 1080×1920、30fps、30秒前後、ポップ、ナレーションなし。色は紫 #825dab ×白、強調に黄色。文字は M PLUS Rounded 1c。
- **最初のロゴ画面は1.8秒**（`tonpedia_pop.mp4` の頭）。冒頭にみんなの「とんペディア！」の声（Drive の音声をノイズ除去・EQ・コンプで整えて0.2秒から）。
- とん平（豚のキャラクター）は全場面に小さく出す。
- 強調したい語（とんペディア）以外の文字は小さく。1行に収める。
- アプリの画面は**スマホの枠に入れて全画面**で見せる。上の時計・電池は切り落とす。下のナビバーは最新版（全部アイコンが埋まったもの）にそろえる。説明カードはスマホに重ねず下に置く。
- 操作動画は速すぎないように（0.85〜1倍）。途中から始まったように見せない（立ち上げた画面・止まった画面から始める）。
- **ぶつっと切れる切り替えは嫌**：場面はクロスフェード、機能と機能の間は左へのスワイプではっきり区切る。
- 効果音は**少なめ・シンプル**、AIっぽい電子音は避け、リールでよくある実録音系（Kenney の CC0 素材）。とん平が出るときの音・ロゴのポン・最後のポン・連続するピコピコは入れない。
- 最後は「くわしくはホームページへ」だけ（URLやinfo欄は不要）。
- BGM はしゃろう「SUMMER TRIANGLE」（OpenTracks。商用OK・クレジット不要）。**ロゴ画面から切り替わる瞬間に音楽を始める**（`add-bgm.sh` の6番目の引数＝ロゴ画面の長さ）。全体は -16 LUFS 前後、声は BGM より約10dB大きく。

## 3. 仕組み（`video/app-intro/`）

| ファイル | 役割 |
|---|---|
| `overlay.html` | テロップ・とん平・スマホ枠など、映像の上に乗るものを全部HTML/CSSで作る。`setTime(t)` で時刻 t の見た目になる。場面表 `S` はロゴ画面の長さ `OPEN`（`?open=` で渡す）からの相対時刻。効果音のタイミングも `window.SFX_CUES` に書く |
| `render-overlay.mjs` | Playwright で HTML を1コマずつ透明PNGに書き出し、`sfx_cues.json` も出す |
| `build.sh` | 背景映像（`BG=( ... )` の区間表）、スマホの中の操作動画、テロップ、声、効果音を ffmpeg で合成。`OPEN=1.8 ./build.sh <assets> <footage> <work> <out.mp4>` |
| `sfx.py` | 効果音を音量をそろえてタイミングどおりに並べる |
| `gc-card.html` / `build-gc.sh` | GC版：最後に白いカード（ラボのロゴ＋「は」／Giving Campaign 2026 に参加中（青 #1e2b99）／Canva の GC 投稿画像／「投票お願いします！」）をクロスフェードでつなぐ。`./build-gc.sh <assets> <普通版.mp4> <work> <out.mp4>` |
| `add-bgm.sh` | BGM を重ねる（声の間は下げる、最後1.5秒でフェードアウト、-16 LUFS）。`./add-bgm.sh <動画> <BGM> <out> 0 -24 <音楽を始める秒>` |
| `sfx/` | Kenney の CC0 効果音とライセンス |

作業用の素材（Drive から落とした動画・画像・BGM）と途中ファイルはスクラッチパッドに置き、リポジトリには入れない。完成品だけ `output/` に置く。

コマ書き出しは時間がかかる（1本数分〜10分）。`run_in_background` で回し、タイムアウトは長め（30分以上）にする。

## 4. 出力と納品

- 出力は4本セット：普通版／GC版 × BGMなし／BGM入り。普通版とGC版は**別ファイル**にする。
- ファイル名：`tompedia_<動画名>_v<版>[_gc][_bgm].mp4`（比較用に作るものは `_open18` のように違いを名前に入れる）。
- **Drive への動画のアップロードはできない**（Drive MCP は中身をbase64でツールに渡す方式で、数MBの動画は送れない）。動画はチャットで送り、Drive の `とんペディア紹介動画` フォルダ（ID `1aBIyxdPBBv7bL56dQQCbvkAq1iIfYfI2`）へはユーザーに置いてもらう。テキスト（投稿文など）は Drive に保存できる。
- Drive に文章を保存するときは `create_file` の `textContent` だと絵文字が文字化けする。保存後に Google Docs の `replaceAllText` で直すか、読み返して確認する。
- Drive から大きい動画を落とすときは、ユーザーに「リンクを知っている全員」に共有設定を変えてもらい、`drive.usercontent.google.com` から curl で落とす。

## 5. Instagram 投稿文

`aidlc-docs/<動画名>/04-instagram-caption.md` に普通版・GC版の2つを書き、同じものを Drive の `とんペディア紹介動画` フォルダに Google ドキュメントで保存する。

- 1行目は動画の冒頭と同じ問いかけにする（最初の2行しか見えないため）。GC版は先頭に GC 参加と投票期間。
- 機能の文言・数字は動画のテロップとそろえる。URLは「プロフィールのリンクから」。
- わからない情報（投票ページのURLなど）は作らず `【要確認：〇〇】` にする。
- ハッシュタグは10個前後（#とんペディア #東北大学 #東北大 #東北大生 #仙台 #大学生 など。GC版は #GivingCampaign #GivingCampaign2026 #学生団体 も）。
