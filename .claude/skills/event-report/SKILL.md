# イベントレポート作成スキル（とんペディア_ラボ）

とんペディア_ラボがInstagramに投稿する「Event Report／イベント開催報告」カルーセルを、Canva上の既存の型を複製して作る。
ゼロから新規デザインを生成しない。フォントや装飾はCanva MCPから指定できないので、**必ず型を `copy-design` で複製してから中身を差し替える**。

## 0. 進め方（自動モード・2026-11-21〜）

本人の方針：**「〇〇のイベレポ作って」と頼まれたら、構成案の確認なしに下書きまで一気に進める。確認は保存（commit）の前の1回だけ。**

1. 素材を集める（2章）。足りない情報は止まらずに `【要確認：〇〇】` を入れて進む
2. 型を判定する（1章）。迷う場合だけ、作り始める前に1回だけ聞く
3. 構成案を作り、`aidlc-docs/event-report-<イベント名の英字>/plan.md` に保存する（本人には見せずに先へ進む）
4. Canva で複製 → 文字と写真の差し替え → 自己チェック（3章 Step 2〜5）
5. Instagram の投稿文を作る（Step 6 を必ずやる）
6. 本人に「サムネイル・投稿文・要確認の一覧・差し替えていない写真枠」をまとめて見せ、OK をもらってから保存する
7. 保存したデザインは Canva の「とんペディアラボ / イベントレポート」フォルダ（`FAHbn3KmSrQ`）に入れる

デザインの決まりは、claude.ai のデザインシステム「とんペディア イベントレポート」（https://claude.ai/artifact/8VXDLuHRoSiqyyYQaSWXFq）にもまとめてある（中身は下の references と同じ）。

> **Canva のアカウントについて（2026-11-22〜）**：使うのは中西悠仁の個人アカウント。以前の型（`catalog.md` の古い ID）は読めないので、Claude が作り直した型を使う。
> - フォルダ：「とんペディアラボ」`FAHbnzFlt8M` ／ その中の「イベントレポート」`FAHbn3KmSrQ`（できたレポートはここに入れる）
> - **A型の型**：`DAHbn8Dp-is`「型＿A型（自主開催）」4ページ（表紙・導入・ありがとう・クロージング）
> - **B型の型**：`DAHbn_mZyF8`「型＿B型（企業とのイベント）」4ページ（表紙・写真2枚＋本文・写真1枚＋本文・クロージング）
> - 作り直した型の注意：表紙の文字以外（本文・縦見出し・swipe）は、ツールから字体を指定できず標準の字体になっている。縦見出しは1文字ずつ改行した横書きで代用。罫線は Canva の最小の太さ（8px）。クロージングは以前のページの画像（横720px）を敷いている。キャプションと Photo Collection のページはまだない（必要なら A型の型にページを足す）。

参照ファイル（作業前に必ず読む）:
- `references/design-spec.md` … 2つの型のレイアウト・色・フォント・座標・ページ構成の定義
- `references/writing-guide.md` … 文章の構成・文字数・トーン・表記ルールと実例
- `references/catalog.md` … 既存レポートの一覧、複製元にするデザインID、作成途中・対象外のデザイン

## 1. 型の判定

| 型 | 見分け方（表紙） | 使う場面 | 複製元 |
|---|---|---|---|
| **A：自主開催（白）** | 「Event Report」が**白文字**。紫地にラベル「イベント開催報告」。写真の上に大見出し＋サブタイトル | とんペディア_ラボの単独主催（メンバー向けの勉強会、ハッカソン、新歓など）、学生団体との合同開催、ブース出店 | `DAG4ZeHkRQk`（01 manabyハッカソン） |
| **B：企業とのイベント（紫）** | 「Event Report」が**紫文字**で上部が白帯。「Sponsored by ＋企業ロゴ」。日付の丸が紫で文字が白 | **企業と一緒に行ったイベントはすべてB**（企業の協賛・共催、企業との交流会、就活支援企業やコミュニティ運営企業とのコラボなど） | `DAHOC235odQ`（13 TDK） |

- 判定ルール：**企業が関わるイベントは基本的にB**（ユーザーの方針）。「Sponsored by」には相手企業のロゴを入れる。
- 14 BeConnect は白（A）で作られているが、これは誤り。企業とのコラボなので本来はB。前例として真似しない。
- 例外の可能性があるもの：自主開催の勉強会に企業の方を講師として招いただけのケース（02 就活イベント、12 勉強会はAで作られている）。この場合と、判断に迷う場合は、作り始める前にユーザーに「A（自主開催）とB（企業とのイベント）のどちらにしますか？」と1回だけ聞く。
- ピンクの表紙（09 スプフェス、10 夜桜を見る会）は型として扱わない。ユーザーから明示的に頼まれない限り使わない。

## 2. 入力として集める情報

### 素材の置き場所
- **Google ドライブ**：`tompedia / イベント`（フォルダID `1K_nMynjij7BykrG-UFsp0O0yzoMQ-Cs1`）の下に、イベントごとのフォルダ `YYYY-MM-DD_イベント名`
  - 「メモ」：Google ドキュメント。テンプレートは同じフォルダの「イベントメモ_テンプレート（コピーして使う）」（`templates/event-memo.md`）
  - 写真：jpg・png・heic。ファイル名が「表紙_」で始まるものを表紙にする。なければ人が多く写っている横長でない写真を選ぶ
  - B型なら企業ロゴの画像
- **チャット**：Discord・Slack の報告（このセッションからは読めない）は、メモの「Discord・Slack の報告」欄か、チャットに貼られたものを使う。両方あれば両方読む

### 探し方
1. `search_files` で `parentId = '1K_nMynjij7BykrG-UFsp0O0yzoMQ-Cs1'` のフォルダから、頼まれたイベント名・日付に合うものを探す。見つからない・複数あるときだけ本人に聞く
2. フォルダの中を `search_files`（`parentId = <フォルダID>`）で一覧にし、「メモ」を `read_file_content` で読む
3. 写真は `download_file_content` で取得する（1ファイル10MBまで）。HEIC は `pillow-heif`（`pip install pillow-heif`）で JPG に変換し、向きを直して長辺2000pxにする：
   ```python
   import pillow_heif; from PIL import Image, ImageOps
   pillow_heif.register_heif_opener()
   im = ImageOps.exif_transpose(Image.open(src)).convert('RGB'); im.thumbnail((2000, 2000)); im.save(dst, quality=88)
   ```
4. Canva へは `create-upload-url` で発行した URL にバイト列を送って取り込む（Step 4）

### 集める項目
必須
1. イベント正式名称（表紙サブタイトルになる。例：「つくってまなぶ！はじめてのWEBサイトづくり 2days」）
2. 開催日（複数日も可）
3. 開催場所
4. 主催／協賛／協力の関係（型の判定に使う。Bの場合は企業の正式名称と、ロゴ画像の有無）
5. 対象者と参加人数（わかる範囲で）
6. 当日の内容（プログラム、登壇者の会社名・役職・氏名、ワークの内容など）
7. 写真（表紙1枚＋本文で2〜8枚。Photo Collectionを作るなら追加で6〜8枚）

あると良い
8. 開催の背景や目的（なぜやったか、団体の思い）
9. 参加者の声（「」で引用できる生の言葉）
10. 印象に残った場面（キャプションのネタ）
11. 謝辞の対象（協賛、協力、会場、講師）

元ネタがSlack・Notion・Googleドキュメントなどにあると言われたら、該当するコネクタで読んで抽出する。

## 3. 手順

### Step 1：構成案を作る（Canvaを触る前）
`references/writing-guide.md` に従って、ページごとに次の表を作り、`aidlc-docs/event-report-<イベント名の英字>/plan.md` に保存する。**自動モードでは本人に見せずに Step 2 へ進む**（本人が「構成案を先に見せて」と言ったときだけ見せて待つ）。

```
P1 表紙：大見出し / サブタイトル / 日付 / （B：スポンサー名）/ 使う写真
P2 本文：縦見出し / 本文 / 写真
P3 …
P最後-1 Photo Collection（任意）
P最後 クロージング（固定。編集しない）
```
- ページ数の目安：Aは5〜8ページ、Bは3〜4ページ（`design-spec.md` の「ページ構成パターン」を参照）。
- 文字数は `writing-guide.md` の上限を必ず守る（はみ出しが一番多い失敗）。
- 写真の割り当て（どの写真をどの枠に入れるか）も表に書いておく。

### Step 2：型を複製する
1. `mcp__Canva__copy-design` で複製元（A：`DAHbn8Dp-is`、B：`DAHbn_mZyF8`）を複製する。使わないページがあれば `page_numbers` で必要なページだけ複製する（クロージングページは必ず含める）。
2. 本文ページのレイアウトを別の既存レポートから借りたい場合は、そのページだけを複製して最後に手動で統合してもらう（`merge-designs` が使える場合はそれを使う）。
3. タイトルを `イベントレポートNN＿イベント名` に変更する（`update_title`）。NNは `catalog.md` の最大番号＋1。最新の番号は `search-designs` で「イベントレポート」を検索して確認する。

### Step 3：テキストを差し替える
1. `read-design` に `open_transaction: true` を付けて、複製したデザインの要素一覧（locator_id）を取得する。
2. `edit-design`（`finalize: "keep_open"`）でページごとに `replace_text` を実行する。書式（フォント・色・サイズ）は元の要素のものが引き継がれる。
   - 新しく `add_text` で要素を作らない（フォントが型と変わってしまう）。足りない場合は、同じページの既存テキスト要素を流用するか、別のレポートから該当ページを複製する。
   - 型に残っている元のイベントの文章（例：「manaby」「プログラミングへの興味が高まった２日間」）は**すべて**置き換えるか削除する。最後に `read-design` の全文から旧イベントの固有名詞を検索し、残っていないことを確認する。
3. 日付は `YYYY\nMM.DD` の形式（例：`2026\n06.23`。複数日は `2025\n10.18,19`）。

### Step 4：写真を差し替える
- 写真の取り込み方法：
  - 公開URLがある → `upload-asset-from-url`
  - チャットに添付されたファイルやローカルファイル → `create-upload-url` で発行したURLに生のバイト列をPOSTする
  - すでにユーザーのCanvaにある → `get-assets` で探す
- `update_fill` で、写真の枠（`isMediaReplaceable: true` の rect／shape）の画像を差し替える。`alt_text` には何の写真かを短く書く。
- 写真が手元にない枠は差し替えずに残し、最後に「差し替えが必要な写真枠：P2の上の写真、P3の左下…」とリストで伝える。旧イベントの写真が残っていることを必ず伝える。
- B型のスポンサーロゴは、表紙の「Sponsored by」の右にあるロゴ枠を `update_fill` で差し替える。
- **触らない要素**：フッターのTompedia Laboロゴ、クロージングページの背景、ページ内の紫の罫線、マスコット（ぶた）のイラスト。

### Step 5：プレビューして保存する
1. `read-design` で全ページのサムネイルを取得し、次の点を確認する：文字のはみ出し・重なり、旧イベントの文章の残り、写真の切れ方。
2. 問題があれば `resize_element`／`crop_media`／文章の短縮で直す。文字のはみ出しは、まず文章を短くして直す（フォントサイズは変えない）。
3. サムネイルをユーザーに見せて、**明示的なOKをもらってから** `edit-design` を `finalize: "commit"` で実行する。OKが出る前に保存しない。
4. 保存したら、`move-item-to-folder` で Canva の「とんペディアラボ / イベントレポート」フォルダ（`FAHbn3KmSrQ`）に移す。
5. デザインの編集URLと、残っている作業（写真の差し替え、要確認の項目）、投稿文をまとめて伝える。

### Step 6：投稿キャプション（自動モードでは必ず作る）
Instagram のキャプションを作り、`plan.md` の最後に書いて、確認のときに一緒に見せる（`writing-guide.md` の「キャプション」を参照）。

## 4. やってはいけないこと
- `generate-design` などで新しいデザインをゼロから作る（型の見た目が再現できない）。
- 元の型デザイン（01・13など既存のレポート）を直接編集する。必ず複製してから作業する。
- ユーザーの承認なしに `commit` する。
- 写真や参加人数、参加者の声を**捏造する**。不明な点は `【要確認】` にする。
- ピンクの型を使う／07・16など作成途中のデザインを複製元にする。
