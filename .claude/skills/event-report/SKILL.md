# イベントレポート作成スキル（とんペディア_ラボ）

とんペディア_ラボがInstagramに投稿する「Event Report／イベント開催報告」カルーセルを、Canva上の既存の型を複製して作る。
ゼロから新規デザインを生成しない。フォントや装飾はCanva MCPから指定できないので、**必ず型を `copy-design` で複製してから中身を差し替える**。

参照ファイル（作業前に必ず読む）:
- `references/design-spec.md` … 2つの型のレイアウト・色・フォント・座標・ページ構成の定義
- `references/writing-guide.md` … 文章の構成・文字数・トーン・表記ルールと実例
- `references/catalog.md` … 既存レポートの一覧、複製元にするデザインID、作成途中・対象外のデザイン

---

## 1. 型の判定

| 型 | 見分け方（表紙） | 使う場面 | 複製元 |
|---|---|---|---|
| **A：自主開催（白）** | 「Event Report」が**白文字**。紫地にラベル「イベント開催報告」。写真の上に大見出し＋サブタイトル | とんペディア_ラボの主催。学生団体やコミュニティとの合同開催、外部講師を招いた勉強会、ブース出店も含む | `DAG4ZeHkRQk`（01 manabyハッカソン） |
| **B：企業協賛（紫）** | 「Event Report」が**紫文字**で上部が白帯。「Sponsored by ＋企業ロゴ」。日付の丸が紫で文字が白 | 企業が協賛・共催したイベント（企業との交流会、企業との共同開催のキャリアイベントなど） | `DAHOC235odQ`（13 TDK） |

- 判定基準は「**企業をスポンサーとしてロゴ付きで表記するか**」。企業の社員が講師として登壇するだけ（例：02 就活イベント、12 勉強会）や、コミュニティとのコラボ（例：14 BeConnect）はAで作られている。
- 迷ったら、作り始める前にユーザーに「A（自主開催）とB（企業協賛）のどちらにしますか？」と1回だけ聞く。
- ピンクの表紙（09 スプフェス、10 夜桜を見る会）は型として扱わない。ユーザーから明示的に頼まれない限り使わない。

## 2. 入力として集める情報

ユーザーから受け取る（足りないものだけ聞く。全部そろうまで止めない。不明な項目は `【要確認：〇〇】` を入れて進める）:

必須
1. イベント正式名称（表紙サブタイトルになる。例：「つくってまなぶ！はじめてのWEBサイトづくり 2days」）
2. 開催日（複数日も可）
3. 開催場所
4. 主催／協賛／協力の関係（型の判定に使う。Bの場合は企業の正式名称と、ロゴ画像の有無）
5. 対象者と参加人数（わかる範囲で）
6. 当日の内容（プログラム、登壇者の会社名・役職・氏名、ワークの内容など）
7. 写真（表紙1枚＋本文で2〜8枚。Photo Collectionを作るなら追加で6〜8枚）

あると良い
8. 開催の背景や目的（なぜやったか、団体の思い）
9. 参加者の声（「」で引用できる生の言葉）
10. 印象に残った場面（キャプションのネタ）
11. 謝辞の対象（協賛、協力、会場、講師）

元ネタがSlack・Notion・Googleドキュメントなどにあると言われたら、該当するコネクタで読んで抽出する。

## 3. 手順

### Step 1：構成案を作る（Canvaを触る前）
`references/writing-guide.md` に従って、ページごとに次の表を作り、ユーザーに見せる。

```
P1 表紙：大見出し / サブタイトル / 日付 / （B：スポンサー名）/ 使う写真
P2 本文：縦見出し / 本文 / 写真
P3 …
P最後-1 Photo Collection（任意）
P最後 クロージング（固定。編集しない）
```
- ページ数の目安：Aは5〜8ページ、Bは3〜4ページ（`design-spec.md` の「ページ構成パターン」を参照）。
- 文字数は `writing-guide.md` の上限を必ず守る（はみ出しが一番多い失敗）。
- ユーザーのOKが出たら Step 2 に進む。修正があれば反映してもう一度見せる。

### Step 2：型を複製する
1. `mcp__Canva__copy-design` で複製元（A：`DAG4ZeHkRQk`、B：`DAHOC235odQ`）を複製する。使わないページがあれば `page_numbers` で必要なページだけ複製する（クロージングページは必ず含める）。
2. 本文ページのレイアウトを別の既存レポートから借りたい場合は、そのページだけを複製して最後に手動で統合してもらう（`merge-designs` が使える場合はそれを使う）。
3. タイトルを `イベントレポートNN＿イベント名` に変更する（`update_title`）。NNは `catalog.md` の最大番号＋1。最新の番号は `search-designs` で「イベントレポート」を検索して確認する。

### Step 3：テキストを差し替える
1. `read-design` に `open_transaction: true` を付けて、複製したデザインの要素一覧（locator_id）を取得する。
2. `edit-design`（`finalize: "keep_open"`）でページごとに `replace_text` を実行する。書式（フォント・色・サイズ）は元の要素のものが引き継がれる。
   - 新しく `add_text` で要素を作らない（フォントが型と変わってしまう）。足りない場合は、同じページの既存テキスト要素を流用するか、別のレポートから該当ページを複製する。
   - 型に残っている元のイベントの文章（例：「manaby」「プログラミングへの興味が高まった２日間」）は**すべて**置き換えるか削除する。最後に `read-design` の全文から旧イベントの固有名詞を検索し、残っていないことを確認する。
3. 日付は `YYYY\nMM.DD` の形式（例：`2026\n06.23`。複数日は `2025\n10.18,19`）。

### Step 4：写真を差し替える
- 写真の取り込み方法：
  - 公開URLがある → `upload-asset-from-url`
  - チャットに添付されたファイルやローカルファイル → `create-upload-url` で発行したURLに生のバイト列をPOSTする
  - すでにユーザーのCanvaにある → `get-assets` で探す
- `update_fill` で、写真の枠（`isMediaReplaceable: true` の rect／shape）の画像を差し替える。`alt_text` には何の写真かを短く書く。
- 写真が手元にない枠は差し替えずに残し、最後に「差し替えが必要な写真枠：P2の上の写真、P3の左下…」とリストで伝える。旧イベントの写真が残っていることを必ず伝える。
- B型のスポンサーロゴは、表紙の「Sponsored by」の右にあるロゴ枠を `update_fill` で差し替える。
- **触らない要素**：フッターのTompedia Laboロゴ、クロージングページの背景、ページ内の紫の罫線、マスコット（ぶた）のイラスト。

### Step 5：プレビューして保存する
1. `read-design` で全ページのサムネイルを取得し、次の点を確認する：文字のはみ出し・重なり、旧イベントの文章の残り、写真の切れ方。
2. 問題があれば `resize_element`／`crop_media`／文章の短縮で直す。文字のはみ出しは、まず文章を短くして直す（フォントサイズは変えない）。
3. サムネイルをユーザーに見せて、**明示的なOKをもらってから** `edit-design` を `finalize: "commit"` で実行する。OKが出る前に保存しない。
4. 保存したら、デザインの編集URLと、残っている作業（写真の差し替え、要確認の項目）をまとめて伝える。

### Step 6（任意）：投稿キャプション
ユーザーに頼まれたら、Instagramのキャプションも作る（`writing-guide.md` の「キャプション」を参照）。

## 4. やってはいけないこと
- `generate-design` などで新しいデザインをゼロから作る（型の見た目が再現できない）。
- 元の型デザイン（01・13など既存のレポート）を直接編集する。必ず複製してから作業する。
- ユーザーの承認なしに `commit` する。
- 写真や参加人数、参加者の声を**捏造する**。不明な点は `【要確認】` にする。
- ピンクの型を使う／07・16など作成途中のデザインを複製元にする。
