# 文章ガイド（イベントレポート）

既存レポート（01〜05、12〜15）の文章から抽出したルール。

## トーンと表記
- です・ます調。丁寧だけど硬すぎない。場面の描写には「、、、」や「！」も使ってよい（01、03）。
- 自分たちの名前は **「とんペディア_ラボ」**（アンダースコア）。メンバーは「とんペディア＿ラボのメンバー」「とんペディアのエンジニア」と書く。
- 企業や外部の人には必ず「様」を付ける：「DeNA様」「TDK株式会社様」「株式会社かい始 代表取締役の深井有様」。2回目以降は「〇〇様」と略してよい。
- 時期は「10月半ば」「11月初旬」「6月下旬」「2月半ば」のようにぼかした言い方が基本。一日だけのブース出店などは「9月3日」と日付をはっきり書いてもよい。
- 場所は通称で書く：「川内キャンパス」「川内北キャンパス」「青葉山コモンズ」「仙台GIGS」。
- 数字：参加人数などは「約40人」「10名以上」「50名」。全角か半角かは型に合わせ、1つのレポートの中で揃える。
- 参加者の声は「」で引用し、「〜との声をいただきました／聞かれました」でつなぐ。
- 段落の頭は全角スペース「　」。

## 表紙
- **大見出し**：何をしたかを一言で。最後は「開催！」「開催しました！」「出店しました！」「交流できました！」など。3〜4行（B型は3行）に収まるよう `\n` で改行位置を決める。
  - A型の例：「ＷＥＢ開発を\n２日で学べる\nイベントを\n開催！」「東北大生と\n首都圏の大学生との\n就活情報格差を\nなくしたい！」「オープンデータを\n活用するための\n勉強会を行いました」「宮城大学Brushと\n交流イベント開催！」
  - B型の例：「TDK様と\nキャリア相談の\nイベントを開催！」「DeNA様と\n交流会を開催\nしました！」
  - 「誰と」「何を」を入れ、イベントの価値（数字や目的）がわかるとより良い。
- **サブタイトル（A型）**：イベントの正式名称。例：「90分で丸わかり！\n１・２年生のための就活講座」「とんペディア_ラボ×Brush 2026新年会」。
- **日付**：`YYYY\nMM.DD`。複数日は `MM.DD,DD`。

## 本文の流れ（A型）
1. **導入**（A-intro、約200文字）：いつ・どこで・誰と（協賛／協力）・誰向けに・何というイベントを開催したか。2段落目で背景や団体の思い。
   > 10月半ば、仙台市の上場企業manabyに協賛をいただき、とんペディア_ラボの主催としては初となるオフラインイベント「つくってまなぶ！はじめてのＷＥＢサイトづくり２days」を開催しました。
   > 実は私たちは、「エンジニアリングを挫折せず学べる環境をつくりたい」という思いから始まった団体です。…
2. **背景・課題**（任意、約200文字）：なぜ今このイベントが必要だったのか（例：東北と首都圏の就活の情報格差）。
3. **当日の様子**（1〜3ページ、各150〜250文字）：プログラム、登壇者のお話、ワークの内容、参加者の様子。写真のキャプションは短く、場面の盛り上がりを伝える（「受賞者は\n自分の作品を\n発表します！」「1ゲーム目は Ito」「みんなで昼食を食べて\n午後も頑張りました！」）。
4. **成果・参加者の声**：「〜との声をいただき、〜する機会を提供することができました。」
5. **締め**（A-thanks、縦見出し「ご参加ありがとうございました」）：
   - 今後の決意：「とんペディア_ラボでは、今後も〜していきます。」「この経験を糧に今後の活動をさらにレベルアップさせていきます。」
   - 謝辞（最後の1文）：「ご参加いただいた皆さん、協賛いただいた〇〇様、ご協力いただいた〇〇様、ありがとうございました。」
6. **Photo Collection**（任意）：文章なし。

## 本文の流れ（B型）
2〜3段落で完結させる。
1. 「〇月〇旬、〇〇様のご協賛のもと／〇〇様と共同で、〜を開催しました。」
2. **企業の紹介を1文入れる**：「〇〇様は、〜を手がける〜な企業です。」（例：「TDK株式会社様はスマートフォン、自動車、産業機器などに組み込まれる電子部品等を製造・販売する世界的メーカーです。」）
3. 登壇した社員の方の紹介と、お話やワークの内容。
4. 参加者の声、学び。
5. 締め：「〇〇の皆様、ありがとうございました！」／「今回の経験をエネルギーに、さらに面白いサービスをつくっていきます。〇〇様、ありがとうございました！」

## チェックリスト
- [ ] 前のイベントの固有名詞（manaby、Brush、TDKなど）が残っていない
- [ ] 協賛・協力・講師の名前に「様」が付いている
- [ ] 謝辞に、関わった団体や企業が全員入っている
- [ ] 文字数の上限（design-spec.md）を守っている
- [ ] 捏造した数字や声がない（わからないものは【要確認】）
